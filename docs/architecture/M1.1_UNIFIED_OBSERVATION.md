# M1.1 — Unified observation contract

## Decisions and scope

The contract version is `1.0.0`. `Observation` in `app/schemas/observation.py` is a frozen Pydantic v2 external contract. Nested contracts forbid unknown fields. Fields are explicit and IDs are bounded ASCII tokens, suitable for pseudonyms, not names. No automatic ID, timestamp, confidence, or measurement generation occurs. No AI, API, storage, or clinical logic is implemented.

Scope is a discriminated union: astronaut (mission and astronaut IDs), spacecraft (mission and spacecraft IDs), compartment (mission, spacecraft, compartment IDs), or mission (mission ID). Cross-scope fields are rejected rather than ignored. Metric definitions constrain valid scope kinds. IDs are not verified against an external mission registry in this milestone.

Measurement is a discriminated union: finite numeric with explicit unit, strict boolean, categorical token, or unavailable with a coded reason. Numeric strings and booleans are not numbers. JSON numbers, including integers, may represent numeric measurements. Zero is a valid physical value, never a missing sentinel. Missing/unavailable records retain metric and scope metadata but have no measurement value or unit; canonical unit remains discoverable from the registry.

## Starter registry

There are no implemented scenarios yet. These six metrics are a deliberately small proposed vocabulary for initial synthetic scenarios, requiring architectural review before expansion. The registry and its entries are immutable.

| Metric | Domain | Kind | Canonical unit / states | Scope | Physical constraint |
| --- | --- | --- | --- | --- | --- |
| `heart_rate` | physiological | numeric | `bpm` | astronaut | nonnegative |
| `ambient_pressure` | environmental | numeric | `Pa` (absolute pressure) | spacecraft, compartment | nonnegative |
| `absorbed_dose` | radiation | numeric | `Gy` | astronaut, spacecraft, compartment | nonnegative |
| `sleep_state` | behavioral | categorical | `awake`, `asleep` | astronaut | categorical membership |
| `gravity_magnitude` | altered_gravity | numeric | `m/s2` | astronaut, spacecraft, compartment | nonnegative magnitude |
| `exercise_active` | mission_context | boolean | true/false | astronaut, mission | strict boolean |

Physical constraints are not clinical ranges or safety limits. There are no physiological upper limits, alert thresholds, medical actions, or probability estimates. `absorbed_dose` is a source-reported scalar: integration window and detector calibration are not defined; it must not be treated as a dose rate or used for operational radiation recommendations.

Only the exact canonical unit is accepted, including case. This intentionally conservative unit policy rejects incompatible dimensions as well as compatible alternative representations: no implicit conversion, aliases, or guessing (`Hz` is not silently converted to `bpm`, `Sv` is not `Gy`, pressure is not dose). Support for conversions requires explicit reviewed conversion rules and provenance later.

## Structural validation versus quality

Structural validation rejects unsupported versions, domains, metrics, unit/kind mismatches, unknown categorical states, invalid IDs/scopes, malformed provenance, invalid confidence, non-finite measurements, naive timestamps, and inconsistent quality metadata. Rejected data cannot become an `Observation`; future ingestion should retain raw rejected material securely in a separate quarantine record, not force malformed data through this schema. No quarantine storage is implemented.

`validate_observation` exposes structured location/code issues without input values, free-form error messages, or Pydantic context. It suppresses exception chaining for ordinary display; callers must never serialize internal traceback locals or exception context. Direct Pydantic `.errors()` can include input values by default; use this boundary for untrusted input and do not log raw validation errors. Models hide inputs in their standard error text, but field names supplied by a producer remain untrusted metadata.

`evaluate_quality` is a pure second step. It preserves source status and reasons and reports any physical-domain violation as invalid. It neither mutates the observation nor discards a questionable reading. Consumers must use the returned assessment; `quality` on the record means source-declared quality, not proof of physical validity. Assessment is not clinical validation. No heuristic sensor-confidence cutoff is used.

| Source quality | Invariant |
| --- | --- |
| valid | Present typed value; no reason codes |
| suspect | Present typed value; at least one limitation reason |
| invalid | Present typed value; at least one rejection/invalidity reason |
| missing | Unavailable measurement with `not_received`; at least one reason; no sensor confidence |
| unavailable | Unavailable measurement with `not_collected`, `sensor_offline`, or `rejected`; at least one reason; no sensor confidence |

A structurally usable invalid reading remains recorded with its value. If a producer cannot supply any usable value, `unavailable/rejected` expresses that loss. Reason codes must be nonempty tokens and unique. Optional `sensor_confidence` is finite and in [0, 1]; it describes source measurement quality only and is never model prediction confidence. No default confidence is invented.

## Time and provenance

Event `timestamp` is required; `ingested_at` is optional and separate. Both require timezone-aware datetime objects or ISO 8601 strings and normalize to UTC. Epoch numbers, timezone-naive values, malformed dates, ingestion before event time, and Python folded ambiguous local datetimes are rejected. A producer must resolve clock skew or local-time ambiguity explicitly before submission. No wall-clock calls or implicit timestamp repairs occur. Mission-relative time is outside this version.

Provenance requires source type, source ID, method token, and origin. Measured uses sensor/mission-log sources, self-reported uses crew reports, derived uses computation, and simulated uses simulator. Derived records require unique parent observation IDs and transformation version; self-parenting is rejected. Non-derived records cannot carry derivation metadata. Simulated records require scenario ID, run ID, generator version, and a nonnegative integer seed; other origins cannot carry simulation metadata. Referenced parent existence, multi-record cycles, chronological lineage consistency, artifact authenticity, and reproducibility of a generator are not guaranteed by a standalone schema.

## Environment and verification

`backend/pyproject.toml` remains the dependency source of truth; no dependency ranges changed. Installation is explicitly authorized for this milestone and isolated to `backend/.venv`. Provisioning may use a network; application validation/evaluation and tests use no network. `.gitignore` now excludes local environments, caches, secrets, and local SQLite artifacts. A resolved package snapshot is recorded in `backend/requirements-m1.1-resolved.txt`; it captures the tested environment, not a cross-platform hash lock or offline wheel bundle.

Run from `backend`:

```sh
.venv/bin/python -m ruff check app tests
.venv/bin/python -m ruff format --check app tests
.venv/bin/python -m mypy
.venv/bin/python -m pytest
```

Tests use synthetic identifiers and data. `Any` in test payload dictionaries is limited to deliberately malformed external JSON-like fixtures: production contracts and interfaces remain typed. Tests cover the contract's public behavior rather than internal implementation. Tool results and interpreter version are recorded in the milestone delivery report.

## Review risks and M1.2 boundary

Review the starter vocabulary, quality-status semantics, strict canonical units, and clock ordering policy before downstream adoption. Validate on Python 3.11 in addition to the available newer interpreter before claiming minimum-version compatibility. Add a hash-locked dependency set and offline artifact bundle for reproducible deployment. Add mission identity/lineage validation and secure quarantine when ingestion/storage is authorized. The two-step quality API requires downstream orchestration to apply its assessment explicitly.

M1.1 creates an observation foundation, not a generic derived-hypothesis or investigation schema. The existing `evidence.py` and `investigation.py` remain placeholders. M1.2 is not started; proceed only after architectural review and an explicit next scope.

Final quality gates: Ruff lint passes; formatter check passes for all 33 Python files; strict mypy passes for all 33 files; pytest passes all 112 cases (84 observation, 28 quality). Tests execute within the restricted-network environment and require no remote services. Deterministic repeated validation/evaluation is tested explicitly.

The first test run reported 109 passed and three failures, all fixed before delivery. Full failure identities and root error:
