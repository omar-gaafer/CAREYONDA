# M1.2 — Synthetic training data handoff

## Compatibility audit and boundaries

No critical blocker was found in the actual M1.1 contract. Source quality semantics are unchanged: valid values have no limitations; suspect/invalid values retain reasons; missing/unavailable measurements have explicit absence reasons and no numeric sentinel. The existing quality evaluator reports physical violations without mutating evidence. The feature extractor uses only evaluated-valid readings and retains all window evidence IDs for audit.

M1.1 event time and optional ingestion time normalize to UTC; ingestion preceding event time is rejected. The simulator supplies nonnegative ingestion delays. Features sort and filter by event time, not arrival time. The teammate's target interpreter is unknown. CPython 3.14.8 is available and tested; the project still targets Python 3.11+ syntax and strict typing. No Python 3.11 runtime is available here, so minimum-version runtime compatibility is not claimed.

No M1.1 validator or quality semantics were redesigned. Four additive registry entries preserve the original six. Schema version remains `1.0.0`; readers must use the extended registry to accept new metrics. No dependencies were added or installed. Tooling paths now include the sibling simulator so it receives the same lint, formatting, and strict typing checks as the backend. Pytest can import both package roots when run from `backend`.

## Added metrics

| Metric | Domain | Canonical unit / states | Allowed scope | Physical validation |
| --- | --- | --- | --- | --- |
| `cabin_co2_partial_pressure` | environmental | `Pa`, absolute CO2 partial pressure | spacecraft, compartment | nonnegative |
| `sleep_duration` | behavioral | `h` | astronaut | nonnegative |
| `fatigue_self_report` | behavioral | `rested`, `tired`, `very_tired` | astronaut | categorical membership |

These are data semantics, not safety limits. The extractor deliberately uses the specified compartment for CO2, spacecraft for communication delay, and astronaut for individual metrics. It does not combine different scopes or infer occupancy/location relationships. The existing six registry entries are preserved; the simulator emits only the six input metrics required by these scenarios.

## Explicit synthetic assumptions

All values, distributions, and relationships below are arbitrary configurable generator assumptions, not established physiological laws, clinical thresholds, validated normal ranges, or diagnoses. Labels identify generator configurations only. Each episode begins in its assigned condition; there is no onset prediction task or pre-event baseline requirement. Different episodes are independent contexts with separate mission IDs and opaque randomized episode IDs.

Default episodes last 30 samples at one-minute intervals. There are eight episodes for each of four scenarios. A local seeded `random.Random` controls episode order, opaque IDs, numeric noise, state choices, dropouts, and ingestion delays. No wall clock, global RNG, network, or remote dataset is used.

Let `n = noise_scale`, `u(a,b)` be independent uniform draws, and `t` be minutes since episode start. One personal HR offset `u(-8,8)*n` is drawn per episode. Numeric values are floored at zero and rounded to six decimals as part of generating synthetic values; this is not a repair of acquired observations.

- Baseline HR: `baseline_heart_rate + personal_offset + u(-3,3)*n`; default center 72 bpm.
- Baseline cabin CO2 partial pressure: `baseline_co2_pa + u(-5,5)*n`; default center 50 Pa.
- Elevated CO2 scenario: add `co2_increase_pa` (default 120 Pa) to CO2 and independently add `co2_heart_rate_increase` (default 18 bpm) to HR. This chosen association is not a causal or medical claim.
- Sleep duration: repeated noisy reports of the **last completed rest period before episode start**, never a future sleep outcome. Center is `baseline_sleep_hours` (8 h), or `deprived_sleep_hours` (3 h) in sleep deprivation; noise is `u(-0.5,0.5)*n`. Reports can vary as noisy estimates of the same past period.
- Fatigue report probabilities for (`rested`, `tired`, `very_tired`) are (0.7, 0.2, 0.1), or (0.1, 0.3, 0.6) in sleep deprivation. States are synthetic labels for self-report inputs, not a validated scale.
- Recent exercise HR increment: `exercise_heart_rate_increase / (1 + t/exercise_decay_minutes)`, default 45 bpm and 15 minutes. The exercise flag is true during the first `exercise_decay_minutes` of this scenario and false thereafter while HR recovers. This toy trajectory is not a validated exercise response model.
- Communication delay: `communication_delay_seconds + u(-0.2,0.2)*n`, default center 2 s, independent of scenario. It is context, not a scenario target.
- Each observation independently becomes explicitly missing with probability 0.03; underlying scenario labels remain unchanged. Missingness is not converted to zero. Ingestion delay is a uniform integer from 0 to 120 seconds, independent of event-time feature ordering.

Configurable parameters are declared and validated in `SimulationConfig`; see generated manifest for the exact values used. Noise, scenario effect sizes, cadence, start, dropout rate, and arrival delays can be supplied with a JSON config. CLI seed/episode/step/dropout options override that config. The full resolved configuration is exported. Reproducibility is verified in the tested Python environment; cross-version RNG output equivalence is not promised.

## Generate and consume

From the repository root, the exact command used for the delivered dataset is:

```sh
PYTHONPATH=backend backend/.venv/bin/python -m simulator.run_simulation \
  --seed 42 --episodes-per-scenario 8 --steps 30 \
  --output datasets/synthetic/m1_2_seed42
```

The output directory must not already exist; reruns should choose a new directory. No existing data is deleted or overwritten. For another configuration, pass `--config path/to/config.json`, optionally `--window-seconds 300`. Use a distinct seed/output for a held-out dataset.

Delivered artifacts in `datasets/synthetic/m1_2_seed42/`:

| File | Purpose |
| --- | --- |
| `features.csv` | `sample_id` plus 16 numeric feature columns; empty cells represent missing values |
| `labels.csv` | `sample_id` and separate `synthetic_scenario` target |
| `observations.json` | All observation-level evidence, including missing records, scope, event/ingestion times, and simulated provenance |
| `evidence_mapping.json` | Per-sample episode/time/scope context, exact per-feature observation IDs, and all window IDs including rejected/missing evidence |
| `feature_schema.json` | Ordered feature names, units, aggregation, encodings, nullability, temporal and quality policy |
| `manifest.json` | Resolved generation config, counts, balance, quality counts, and SHA-256 hashes for the other six artifacts |
| `README.md` | Short training handoff and limitations |

Delivery counts: **5,760 observations, 960 samples, 32 episodes, 16 features**. Each scenario has **240 samples in eight episodes**. There are **5,612 valid and 148 explicitly missing** observations. The balanced scenario mix is an experimental design, not an operational prevalence estimate.

## Feature names and units

For each numeric metric below, export `<metric>_latest`, `<metric>_mean`, and `<metric>_missing`. CSV order is latest, missing, mean within each metric. Means are arithmetic sample means, not time-weighted integrals.

| Metric prefix | Latest/mean unit | Missing indicator unit |
| --- | --- | --- |
| `heart_rate` | bpm | 1 |
| `cabin_co2_partial_pressure` | Pa | 1 |
| `sleep_duration` | h | 1 |
| `communication_delay` | s | 1 |

Additionally export `fatigue_self_report_latest`, `fatigue_self_report_missing`, `exercise_active_latest`, and `exercise_active_missing`, all unitless (`1`). Fatigue encoding is rested=0, tired=1, very_tired=2; exercise encoding is false=0, true=1. Ordinal fatigue codes are a convenience, not validated interval measurements; no fatigue mean is computed.

All features use the same causal trailing window `(sample_time - 300 seconds, sample_time]`. No future observation, whole-episode normalization, future label, or target-dependent feature transformation is used. Equal event times are resolved by observation ID, independent of input/ingestion ordering. No implicit interpolation or backward fill occurs. Latest selects the last evaluated-valid reading in the window; an explicit missing reading does not erase an earlier usable reading inside that window. The missing flag is 1 only if the window has **no** usable reading for the metric. Empty windows produce null latest/mean rather than zero. Current-time readings are available inputs for current-condition classification, not advance warnings.

This is retrospective event-time export: evidence arriving after the sample time can be included if its **event time** falls inside the window. It does not claim deployment-time availability. An online replay would additionally need an as-of arrival cutoff and is outside M1.2.

Train with **only** the feature names listed in `feature_schema.json`; drop `sample_id` from predictors. Join labels by `sample_id`. Never feed provenance (which explicitly includes scenario IDs), mapping context, IDs, labels, README, or manifest into the model. Split by whole `episode_id` from the mapping, stratifying episode groups where practical; hold out a distinct seed for stronger separation. Random row splits leak overlapping window evidence across partitions. Fit imputers/scalers only on the training partition. No training code or model is implemented here; a teammate can independently load these artifacts and start experiments without running a service.

## Quality gates and limitations

Run from `backend` using the existing environment:

```sh
.venv/bin/python -m ruff check app tests ../simulator
.venv/bin/python -m ruff format --check app tests ../simulator
.venv/bin/python -m mypy
.venv/bin/python -m pytest
```

Tests cover seed reproducibility/variation, all scenarios, schema/UTC ordering, configurable toy effects, scope isolation, physical bounds, units, missing and absent records, quality exclusion, window boundaries, absence of future/target leakage, serialization and artifact consistency, deterministic exports, and refusal to overwrite outputs. All original M1.1 tests remain part of the suite.

This MVP is for synthetic scenario classification, not clinical evaluation, forecasting, probabilistic calibration, or validation of causal hypotheses. Sleep reporting is simplified, episodes have fixed conditions and one crew/cabin context, irregular sampling is not time-weighted, and the starter feature set omits the other four registry metrics. Cross-platform dependency locking and Python 3.11 runtime testing remain open. Large-scale processing is not optimized; groups are scanned per anchor, adequate for the delivered MVP. M1.2 stops at export; no M1.3, AI training, API, database, or frontend work is included.
